## 图片列出的完成能力

- **创建独立 Run**：每次创建都有新的 runId/traceId，执行不依附于 SSE 订阅连接。
- **流式调用模型**：六个型号已逐个真实调用，结果见 models-verification.json。
- **统一 Harness Event**：厂商字段在 Adapter 内转换，Agent/Store 对外只提供统一 RunEvent。
- **SSE 推送、用户取消、断线恢复**：API、页面、CLI 均提供入口；真实 TCP 测试覆盖断线不重跑。
- **Checkpoint 保存、TTFT 统计**：独立历史表、完整快照查看、指定安全边界恢复、首正文延迟、P50/P95。

## 图片底部可见的 5 条验收标准

| 标准 | 检查方法 |
| --- | --- |
| 首个 delta 快速展示 | 页面逐片段追加，服务端不缓存完整答案后才推送；云端响应延迟由模型决定 |
| 不依赖模型 SDK | pyproject.toml 中没有 OpenAI/DashScope SDK，Adapter 直接使用 httpx |
| Run 单一终态 | 页面终态计数为 1，数据库事务拒绝终态之后的事件与状态覆盖 |
| 取消真停止 | 检查上游流 aclose、生成器 finally 和取消后无新正文；云端计费停止时间不由本地连接单方面保证 |
| 断线不重跑 | 同一 runId、seq 延续、model.started 数量不增加 |

## 一次完整的页面演示

1. `docker compose up -d --build --wait`，确认两个容器 healthy。
2. 打开页面，确认 PostgreSQL 已连接；输入 `12 + 30` 并开启工具。
3. 观察 TTFT、模型调用、工具、用量和事件序号。
4. 点击断开订阅，再恢复，确认正文补齐且 model.started 不因订阅增加。
5. 新建较长任务后取消，确认 cancelled 终态只有一个。
6. 查看 Checkpoint 历史，选择工具完成边界，创建子 Run。
7. 检查子 Run 的父运行链接、sourceCheckpointId 与工具调用计数。
8. 浏览 runs/events/checkpoints 的真实数据和表结构，导出 Trace。
9. Docker down/up 后刷新页面，确认记录仍在。

自动验收：`docker compose --profile test run --build --rm tests`。PostgreSQL 测试各自使用独立临时 schema，测试后只清理其自行创建的 schema，不修改应用业务数据。
