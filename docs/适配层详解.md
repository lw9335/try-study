# 阿里云适配层：从 HTTP 字节流到统一事件

建议结合 `gateway/adapters/aliyun.py`、`gateway/model.py`、`tests/test_adapter.py` 阅读。

## 1. 为什么需要适配层

Agent 处理的是“正文增量、思考增量、用量、模型结束和工具调用”。阿里云实际返回的是 `choices[0].delta.content` 等字段。适配层把两者解耦：Agent 只认识 `ModelChunk`，不会到处出现厂商协议判断。

千问与通过同一平台接入的 DeepSeek 文本模型使用相同的兼容协议，因此是同一个 `AliyunAdapter` 配合不同 `ModelProfile`，不需要为每个模型写一套 HTTP 请求。当前接入 4 个 Qwen 与 2 个 DeepSeek，详情见 `模型协议对照.md`。未来接入不同协议的供应商，只需提供同样的 `stream(request)` 异步生成器。

## 2. 请求映射：build_payload

Agent 传入的 `ModelRequest` 包含 `model/messages/tools/thinking`。适配层把它转换为：

```json
{
  "model": "qwen-plus",
  "messages": [{"role":"user","content":"计算 12 + 30"}],
  "stream": true,
  "stream_options": {"include_usage": true},
  "enable_thinking": false
}
```

开启工具时再加 `tools` 定义。`thinking_mode=optional` 时显式发送 `enable_thinking`；`none` 不发送；`required` 的扩展模型始终思考，不发送关闭开关。不要给所有模型盲目附加相同扩展参数。这里直接使用 HTTP，因此参数位于 JSON 顶层；官方 Python SDK 示例中的 `extra_body` 是 SDK 的传参方式，不是线上 JSON 包装层。

`stream_options.include_usage` 让最后的额外数据块携带用量。这个块可能 `choices=[]`，不能认为“没有 choices 元素就是流结束”。

## 3. 字节流不等于 token，也不等于 JSON

`httpx.Response.aiter_bytes()` 每次返回的字节块由网络决定。一个中文字符可能拆在两个块里，一个 JSON 可能横跨很多块，一个块也可能包含多个 SSE 事件。

`gateway/sse.py` 按顺序完成：增量 UTF-8 解码 → 识别 CR/LF/CRLF 行边界 → 收集多行 data → 遇空行才提交完整 SSEFrame。注释心跳不生成 ModelChunk。EOF 没有空行的半帧丢弃；整个模型流是否完成还要继续检查 DONE。

## 4. 响应映射：_decode

| 阿里云字段/帧 | 统一 ModelChunk | 统一 RunEvent |
| --- | --- | --- |
| `delta.content` | `delta(text=...)` | `model.delta` |
| `delta.reasoning_content` | `reasoning(text=...)` | `model.reasoning` |
| 顶层 `usage` | `usage(usage=...)` | `model.usage` |
| `delta.tool_calls` | 暂存并按 index 聚合 | 工具参数完整后由 Agent 产生 tool 事件 |
| `finish_reason` + `[DONE]` | `finish(reason, tool_calls)` | `model.finished` |
| HTTP/协议/流错误 | `GatewayError` | `run.failed` |

Adapter 不直接生成 RunEvent，因为 `runId/traceId/seq` 属于网关运行状态，由 Store 分配。这样多个模型可以共用一套审计与重放协议。

## 5. 为什么工具参数要先聚合

工具调用可能分成：

```text
index=0, id=call_1, name=add, arguments={"a":12,
index=0, arguments="b":30}
finish_reason=tool_calls
[DONE]
```

第一片 `arguments` 不是完整 JSON，不能马上 `json.loads()`。如果模型并行请求多个工具，还必须按 index 分组拼接，不能把所有 arguments 混到一个字符串。Adapter 返回完整的 `ToolCall`，Agent 再通过工具白名单检查名称与参数。

执行后把 assistant 的 `tool_calls` 与 role=tool 的结果加入消息历史，再调用模型形成最终答案。开启思考时，Agent 还把完整思考片段聚合到内部 `reasoning` 字段，Adapter 在构建下一轮请求时映射成 `reasoning_content`，避免丢失工具推理上下文。完整工具轮次结束后保存 checkpoint；工具结果已经持久化时，从这个 checkpoint 恢复就可以直接进入下一轮模型。

## 6. 结束与失败协议

`finish_reason` 说明模型为什么停止；`[DONE]` 说明供应商事件流正常收尾。本练习要求两个信号都存在。遇 EOF、无效 JSON 或缺少结束标记会失败，不能拿到几段文字就宣布成功。

`stop` 是正常回答，`tool_calls` 交给 Agent 继续处理；`length/content_filter` 等原因会记为 `MODEL_INCOMPLETE`，保留已经输出的事件供审计。工具结束标记和工具参数不一致时按协议错误处理。

HTTP 429、5xx、连接超时等错误标记 `retryable=true`，表示用户可以决定是否创建后续 Run，不代表后台自动重复请求。厂商原始错误响应可能包含敏感信息，因此公开事件只返回脱敏 code/message。

## 7. 取消如何传到阿里云

```text
POST /cancel
    → Store 写入唯一 cancelled 终态
    → asyncio.Task.cancel()
    → CancelledError 进入 Adapter
    → 退出 httpx 的 async with client.stream(...)
    → 关闭上游 HTTP 响应
```

`CancelledError` 不当作普通模型错误吞掉。测试中的真实 `httpx.AsyncByteStream` 会检查 `aclose()` 是否执行，避免仅仅把界面标为取消。

SSE 客户端断开则仅释放订阅者，不调用上述取消路径，所以断线重连不重跑模型。

## 8. 自己动手改一个模型

1. 在 `MODEL_PROFILES` 添加你在百炼控制台已开通的模型 ID。
2. 根据官方说明设置 `family/thinking_mode/tools`，有特殊字段时在适配层按 capability 扩展。
3. 用 `tests/test_adapter.py` 的 MockTransport 检查实际 JSON，不需要密钥即可检查参数映射。
4. 在 `.env` 切换 `MODEL_PROVIDER=aliyun`，确认地域与 Key 匹配。
5. 从 Web 或 Python CLI 创建一个新 Run，查看 TTFT、usage、finish 与工具循环。

这套练习覆盖文本 Chat Completions 与 function calling；图像、音频、多模态内容与其它协议需要另加对应输入类型和适配，不应仅替换 model 名称后假设都能工作。
