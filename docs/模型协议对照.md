# Qwen 与 DeepSeek：什么统一，什么不统一

核验日期：2026-10-18。接入地址：`https://maas.qianwenaiapi.com/compatible-mode/v1`。密钥只放在本地 `.env`，本文与验证记录均不包含密钥。

**结论：本次接入的文本 Chat Completions 请求和流式响应共用协议，模型能力与扩展参数分别配置。** 接入平台统一，不代表模型研发方相同；Qwen 是千问模型，DeepSeek 是通过千问 AI 平台提供的另一模型系列。

## 已配置与验证的型号

| family | model ID | thinking_mode | 真实短文本流 |
| --- | --- | --- | --- |
| Qwen | `qwen-plus` | optional | HTTP 200、stop、DONE |
| Qwen | `qwen3.8-flash` | optional | HTTP 200、stop、DONE |
| Qwen | `qwen3.7-plus` | optional | HTTP 200、stop、DONE |
| Qwen | `qwen-max` | none | HTTP 200、stop、DONE |
| DeepSeek | `deepseek-v4.1-flash` | optional | HTTP 200、stop、DONE |
| DeepSeek | `deepseek-v4-pro` | optional | HTTP 200、stop、DONE |

`GET /models` 返回了 176 个模型条目，其中含图像、语音、向量、第三方直供等模型。不能把完整目录都塞进本练习的纯文本适配器。上表选取了 6 个通用文本模型并逐个真实调用；型号列表存在也不等于某账号一定有调用额度，应以实际调用为准。

Qwen Plus 与 DeepSeek V4.1 Flash 还分别验证了：普通工具循环得到 42；开启思考的工具循环得到 5。详细脱敏记录见 `models-verification.json`。这里只表示所述测试请求成功，不代表验证过所有任务或所有参数组合。

## 统一的部分

| 项目 | Qwen / DeepSeek 共用形式 |
| --- | --- |
| 地址 | `POST {base_url}/chat/completions` |
| 鉴权 | 服务端设置 `Authorization: Bearer <环境变量中的密钥>` |
| 输入 | `model`、`messages: [{role, content}]` |
| 流式开关 | `stream: true` |
| 用量请求 | `stream_options: {include_usage: true}` |
| 正文 | `choices[0].delta.content` |
| 思考过程 | `choices[0].delta.reasoning_content` |
| 工具增量 | `choices[0].delta.tool_calls`，按 index 聚合参数 |
| 模型结束原因 | `choices[0].finish_reason` |
| 流结束 | SSE 的 `data: [DONE]` |
| 用量 | 顶层 usage，最后一帧可能 `choices=[]` |

例如替换模型时，消息内容和 SSE 解码器不必重写：

```python
request = ModelRequest(
    model="deepseek-v4.1-flash",  # 或 qwen-plus
    messages=[{"role": "user", "content": "解释什么是 SSE"}],
    tools=False,
    thinking=False,
)
async for chunk in adapter.stream(request):
    if chunk.type == "delta":
        print(chunk.text, end="", flush=True)
```

平台实际返回的 JSON 不一定逐字段完全一致。本次 `qwen-max` 还返回 `system_fingerprint`，其它所测型号未返回；Adapter 只依赖必要字段并忽略额外元数据，避免将“兼容协议”误写成“JSON 键集合必须相等”。

## 不统一的部分

1. **模型 ID**：从该地址的模型目录和官方说明核对，不能把别的平台 `deepseek-chat/deepseek-reasoner` 名称直接套过来。当前目录没有无版本 `qwen-turbo`，已替换原练习的旧选项。
2. **思考能力**：混合模式可通过 `enable_thinking` 切换；非思考模型不发送这个字段；纯推理模型不能传 false。Profile 使用 none/optional/required，前端也对应禁用或固定开关。
3. **推理强度与预算**：`reasoning_effort/thinking_budget` 的范围和组合限制随型号变化。当前网关不盲目向所有型号添加它们。
4. **工具能力**：是否开放工具由 Profile.tools 控制。后续添加 GLM 等其它系列时，还可能需要 `tool_stream` 等额外配置，不能仅替换 model 后假设完全一致。
5. **工具思考历史**：多轮工具推理需保存历史思考上下文。Agent 使用内部 reasoning 字段，Adapter 映射成 reasoning_content；该字段也随 checkpoint 保存。
6. **模态与协议**：本练习的 content 是文本。图像、音频、实时语音、向量模型可能使用数组内容、其它路径、WebSocket 或不同响应格式，不能由本适配器直接通用处理。

## 代码如何分工

- `gateway/model.py`：6 个 ModelProfile，是阅读模型差异的入口。
- `AliyunAdapter.build_payload()`：读取能力配置，把内部消息和参数转换成平台请求。
- `AliyunAdapter._decode()`：Qwen / DeepSeek 共用的流式响应解析。
- `gateway/agent.py`：只消费 ModelChunk，统一执行工具循环，不按模型名称写 if/else。
- `gateway/store.py`：统一事件序号、状态、审计与 checkpoint，与模型系列无关。

因此新增同协议的 DeepSeek 型号通常只需增加 Profile；遇到真实的协议差异，再修改对应请求/响应映射，不复制整套网关。
