## 已讲的第 20 页内容

- 核心原则：Loop 负责生产事实，HTTP 层负责传输事实。
- 分工：Agent Loop 调模型、执行工具并判断下一步；Run Store 保存运行状态和事件；HTTP/SSE 传事件；页面渲染。
- 三个边界：模型事件不等于 Run 事件；流结束不等于任务成功；取消是控制信号，不能统一当成普通失败。
- 课件使用 `task.started` / `text.delta`；本项目对应使用 `run.started` / `model.delta`，要解释命名映射，不能让用户以为是同一个字面事件名。
- 完整讲解见 `第20页-AgentLoop.md`。

## 练习项目当前状态

- Python / FastAPI / httpx，模型 SDK 非必需；Web 为原生 HTML/CSS/JS，CLI 为 Python。
- Docker Compose 启动 gateway + PostgreSQL 17；本地开发也支持 SQLite。
- 主线：`ModelRequest -> Adapter -> ModelChunk -> Agent Loop -> RunEvent -> Run Store -> SSE -> 客户端`。
- 已实现：事件、SSE 编解码、多模型配置、工具循环、显式取消、事件回放、快照历史、父子 Run、数据库浏览与审计。
- `AliyunAdapter` 对接配置的兼容 Chat Completions 接口；Qwen / DeepSeek 共用适配器，按 profile 处理能力差异。
- 断开订阅不会取消 Run；重新订阅回放事件，不重新发起模型请求。
- checkpoint 保存安全步骤，不保存厂商隐藏生成状态，不能精确续接半个 token；恢复创建子 Run。
- 正常服务关闭产生 `SERVER_SHUTDOWN`；进程意外退出留下的 running Run 在下次启动记为 `PROCESS_INTERRUPTED`。
- 当前加法工具是纯函数。独立的副作用工具操作表、业务幂等和外部 exactly-once 执行不属于现有已实现能力。
- 新电脑默认 demo。密钥、本机历史 Run、数据库卷与虚拟环境不随仓库同步。
