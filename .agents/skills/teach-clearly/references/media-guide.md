# 为理解和练习选择媒体

媒体支持核心教学工作流，不能代替练习、反馈和复习。先确定用户要理解哪个关系，再决定载体；优先复用当前案例。

## 文字与图解

采用用户提供的 STE 思路：熟悉词汇、短句、主动语态、明确动作主体和指代。同一对象保持同一名称，一段一个主题。中文不套英文计词规则，普通解释不声称获得标准认证。

定义用短文和例子，对比用表格，层级用结构图，过程用带参与者的流程图或时序图。箭头标动作或数据名称；区分执行和等待、请求和响应，不单靠颜色传递含义。

例如解释工具结果回传：

```text
模型 ──函数名与参数──→ 程序
程序 ──执行调用────→ 工具
工具 ──执行结果────→ 程序
程序 ──下一次请求──→ 模型
```

小型技术图优先 Mermaid 或文本；需要图像生成时按图像技能执行，精确字段仍用可编辑文本。科学图表用标准绘图工具。用户提供的 [STE 图](ste-overview.png)可作信息组织参考。

## HTML 互动演示

当条件变化、状态推进或数据归属难以通过静态说明理解时，使用可操作的演示。优先应用可用的 visualize 技能；用户要求独立网页时遵循可用网站工作流。

- 完成可运行的产物，打开或嵌入并提供可再次访问的结果，不只贴源码。
- 少量控件对应一个学习问题，例如先预测下一步，再点击继续，观察哪个参与者收到哪段 JSON。
- 提供重置、暂停或减少动画的方式，支持键盘，保持文字可读。
- 模拟数据明确标注；检查核心操作与各状态对应的内容。不要为教学模拟擅自调用收费 API。
- 用户仍然不理解时检查演示是否暴露了真正的因果关系，而非只添加更多动画。

## 动画和视频

连续变化、空间关系或长过程适合时间轴表达，用户明确指定视频时也采用。可以借鉴数学讲解动画的逐步推导与视觉直觉，不照搬创作者素材。

先确定学习动作和关键画面，再制作分镜、旁白、字幕与动画；保持标签、声音和数据一致，给用户观察与预测的时间。实际生成后检查画面与讲解对应，再播放或提供文件。

按可用能力使用本地渲染或语音。引用文字中的 API Key 示例不构成使用付费账户的授权。只能做交互动画或分镜时，如实标明实际形式，不称其为已生成视频，不把密钥写入产物。
